# Лабораторная работа 4 — композируемость смарт-контрактов

Гостевая книга Poster проверяет баланс ERC-20 перед публикацией. Используется токен Study Token (STDY) из лабораторной 3. Минимальный баланс — 10 STDY. Ровно 10 токенов достаточно; токены при публикации не списываются. Комиссия оплачивается тестовыми ETH.

- STDY: `0x586da3bd74eE85533FcfcEBad3EDe343dE916e41`, decimals = 18.
- Порог: `10000000000000000000` минимальных единиц.
- Владелец: `0x0D1fB0277bD5581EC4365120AaB5C9b4B34fc49a`.

## Запуск

Нужен Node.js >=22.13 (проверено 24.22.3). В `poster-contract` и `poster-ui` выполнить `npm ci`.

1. В `poster-contract`: `npm test` и `node scripts/prepare.mjs`.
2. В `poster-ui`: `npm test`, `npm run build`, `npm start`.
3. Открыть http://127.0.0.1:3002, выбрать Ethereum Sepolia, подключить MetaMask.

Для локальной проверки в отдельном терминале `poster-contract`: `npm run node`, затем `node scripts/local-check.mjs`. Скрипт создаёт Token и Poster, проверяет отказ аккаунту без токенов и публикацию при ровно 10 STDY; сохраняет адреса в deployment.local.json. При повторном запуске создаются новые экземпляры. Локальная сеть использует общедоступные тестовые аккаунты Hardhat.

## Функции

Подключить кошелёк, проверить баланс и порог, заполнить текст и тег, подтвердить публикацию. При недостаточном балансе показывается предупреждение и отключается кнопка публикации; непосредственно перед отправкой баланс проверяется повторно. Контракт независимо проверяет доступ в `post`.

Владелец может менять токен через `setTokenAddress`, порог через `setThreshold` и передавать владение. При смене токена единицы порога определяются decimals нового токена. Нулевой новый владелец запрещён; setTokenAddress требует адрес с кодом. Это не доказывает соответствие ERC-20: при несовместимом или ложно возвращающем баланс токене доступ может нарушиться.

Список сообщений читается из NewPost. Indexed string tag хранится в журнале в виде хэша, поэтому текст тега извлекается из calldata. Поддерживаются прямые вызовы и вложенные вызовы смарт-аккаунтов MetaMask: кандидат проверяется по тексту сообщения и хэшу тега из события.

## Проверки

11 тестов контракта: успешная публикация без списания токенов, отказ с нулевым балансом, ровно порог и на одну минимальную единицу меньше, актуальный баланс после перевода, управление порогом и токеном, передача прав, запрет нулевого владельца, неинициализированный адрес токена.

3 теста разбора calldata: прямой вызов, вложенный вызов, несовпадающие содержимое и хэш. Production-сборка Next.js включает проверку TypeScript.

`node scripts/check.mjs` проверяет публичное состояние Sepolia и симулирует отказ тестовому адресу с 1,25 STDY. Симуляция не отправляет транзакцию и не расходует ETH. Результаты — `evidence/sepolia.json`.

`node scripts/verify.mjs` повторно отправляет стандартный вход компилятора в Sourcify. Исходники прошли exact-match проверку Sourcify и Blockscout; статус Etherscan не заявляется.
